模型接入 v1（程序书 DeepSeek 可选生成）
========================================

定位：这是程序书生成的辅助能力，不是程序树的判据。默认关闭；只有显式传入 --llm 才调用
DeepSeek，不传时完全走离线模板，存在密钥也不自动启用。程序树的校验、状态、台账与备份
结论永远由内核规则决定，模型只起草程序书正文，不参与判定。

一、调用路径与开关
------------------

1. 程序书由 ptree-cs book 生成，输出 00-程序树/生成/程序书.txt；默认使用离线模板。
2. 显式 ptree-cs book --llm 才发起 DeepSeek 请求。--llm 可以和环境变量、
   全局配置同时存在，但不会改变其他子命令的行为。
3. 不带 --llm 时，不读取 api_key，不发起网络请求，不产生调用日志，行为与旧版完全一致。
4. 程序书之外的总览、落地顺序、标杆看板不走 LLM；备份、校验、变更、健康检查也不走。

二、配置与密钥来源
------------------

1. 密钥按以下优先级读取，先找到先用，不合并多份密钥：
   第一优先级：环境变量 DEEPSEEK_API_KEY。
   第二优先级：全局配置 %USERPROFILE%/.ptree/global.yaml 的 deepseek.api_key。
   第三优先级：credentials.enc 解密后的 deepseek.api_key。
2. 全局配置形状如下，未写的键取默认值：
     deepseek:
       api_key: <密钥>
       base_url: https://api.deepseek.com
       model: deepseek-chat
       timeout_seconds: 60
       max_retries: 1
     credentials.enc 使用与备份凭据相同的 AES-256-GCM 与全局密钥，解密后取
     deepseek.api_key；密钥只在进程内存中使用，不落到临时文件。
3. base_url 与 model 可以被命令行覆盖，优先级为命令行 --base-url / --model
   高于环境变量 DEEPSEEK_BASE_URL / DEEPSEEK_MODEL，高于 global.yaml，高于内置默认值。
   base_url 只接受 https:// 地址；model 只接受非空模型名。非法覆盖按配置错误处理。
4. 任何路径都不把密钥写入日志、台账、生成物、异常消息、MCP 响应或测试快照；
   token 摘要最多显示前 4 位与后 2 位，长度不足 6 时显示 ****。

三、请求参数、超时与重试
------------------------

1. 默认超时 60 秒，可用 deepseek.timeout_seconds 覆盖，范围 5 到 300 秒；
   单次请求超时按整次调用失败处理。
2. 默认重试 1 次，即最多 2 次尝试；只对连接失败、读取超时、HTTP 429 与 5xx 重试，
   401、403、404 与参数错误不重试，直接进入失败处理。重试前等待 1 到 3 秒，不无限退避。
3. 请求温度不高于 0.3，max_tokens 由程序书长度预算控制；提示词只送当前节点、
   相邻契约与必要说明，不整仓发送，也不送 .enc、私钥、凭据或未登记文件。
4. 调用摘要只记录模型名、base_url 主机、耗时、token 数、是否重试与是否回退，
   不记录 prompt 全文与密钥。

四、失败、回退与退出码
----------------------

1. 显式 --llm 但没有配置任何可用密钥：不发起请求，不覆盖已有程序书，退出码 2，
   文案指明按环境变量、global.yaml、credentials.enc 的顺序检查配置。
2. 密钥无效、401 或 403 鉴权失败：按调用失败回退离线模板，退出码 0，并提示检查密钥；
   命令行 --base-url 不是 https 地址或 --model 为空属于参数错误，退出码 2，不写模型生成的
   半成品，已有程序书保持原样。
3. 网络失败、超时、429、5xx、响应无法解析或内容未通过 R31/R34/R37 检查：回退到
   离线模板，重新生成程序书，退出码 0，并打印一条 WARN 说明回退原因。
4. 回退必须整份回退，不允许把模型生成的半段与模板拼接；回退后的程序书与不传 --llm
   的离线模板逐字一致，便于复现与比较。
5. 不带 --llm 时始终退出码 0（除非模板自身写入失败）；备份、校验等其他命令的退出码
   不受本能力影响。

五、生成内容的硬约束
--------------------

1. 生成正文只能引用 program-tree.yaml 与 contracts.yaml 中登记过的节点 id、契约 id、
   files、home、spec 路径；不得编造文件、目录、接口、依赖或验收结论。
2. 文件路径必须来自节点 files、home 或 spec，不能凭模型记忆补全；生成后由内核逐条
   检查引用，发现未登记路径就整份回退模板，不把可疑路径写进 00-程序树/生成/程序书.txt。
3. 模型不得修改节点状态、验收结果、台账、契约或清单；程序书只是只读生成物，不能作为
   落地依据，也不能反向覆盖树数据。
4. 生成内容不得包含密钥、token、密码、私钥、连接串或 credentials.enc 内容；提示词与
   输出都要做同一套脱敏，命中敏感串时放弃该次生成并回退模板。
5. 模型不得把“推测”“大概”“可能”写成事实；不确定的内容留空或要求人工补，不伪造
   真实路径与测试结果。

六、成本与限流建议
------------------

1. 默认优先离线模板；只有需要润色程序书叙述时才加 --llm，批量生成前先估算 token。
2. 按节点分组生成，单次只送当前节点与相关契约；并发不超过 2，避免瞬时打满限流。
3. 设置每日调用次数与费用上限；超过上限直接回退模板并提示，不静默继续烧额度。
4. 429 按 Retry-After 等待；连续失败时熔断本次生成，不循环重试。
5. 缓存同一 tree_version、同一提示版本的生成结果；tree_version 变化或提示模板变化才重算。

七、不该使用 LLM 的场景
-----------------------

1. 校验结果、R01-R46 与 T01-T12 的判定、退出码一律不许由模型决定，必须由内核规则产出。
2. 变更台账、备份台账、备份成功与失败、密钥扫描结论不许由模型决定或改写。
3. 节点状态、父子完成度、已验证证据、退役与替代关系不许由模型判定；模型只能读结果。
4. 密钥、凭据、加密文件、用户隐私数据不送外部 API；需要描述时只送脱敏后的结构摘要。
5. 离线环境、未配置密钥、网络不稳定或成本未获批准时，直接使用模板，不调用 LLM。

八、审计与复现
--------------

1. 每次 --llm 生成都记录 tree_version、模型名、base_url 主机、耗时、token 数与是否回退；
   记录中不含 prompt 全文与密钥。
2. 程序书文件头写明生成方式（离线模板或 DeepSeek 模型名）与生成时间，便于复核。
3. 同一 tree_version 与同一提示版本应得到可比较的结果；模型输出不稳定时以离线模板为准。
4. 规范变更必须同步检查本文件与 程序树规范_v1.txt、校验规则_v1.txt 的口径，不新造规则编号。
